桌面 App本地进程PTY

内置终端与 Claude Code 启动

桌面 App 的中间标签页里有真正的终端。Terminal 标签页在当前项目目录打开你的登录 shell（macOS 上是 zsh 或 bash，Windows 上是 PowerShell），Claude Code 标签页直接启动本机安装的 claude CLI。每个标签页都是 Electron 主进程里的真实 PTY（node-pty），用 xterm.js 渲染，所以颜色、全屏程序、粘贴、调整大小和 Ctrl+C 都和普通终端一样，配色跟随 App 主题。这些终端也和 agent 共享：经你批准后，agent 可以用 terminal_use 工具列出打开的终端、读取输出、向你正在看的那个 shell 输入，或者打开一个自己的终端。Web UI 不暴露主机命令执行。

为什么要真实 PTY

管道不是终端

用普通管道加 TERM=dumb 启动的子进程没有终端设备，Claude Code 这类交互程序会失去光标控制、全屏刷新、颜色和快捷键。

终端语义交给终端模拟器

<pre> 加单行 <input> 无法解释 ANSI、光标移动、备用屏幕、粘贴和 Ctrl+C；xterm.js 可以。

一套主题契约

背景、前景、光标、选区和 ANSI 16 色都来自全站语义 token，所以浅色、暖色和自定义主题与 App 其余部分一致。

方案对比

方案能力选择
node-pty真实 PTY，支持输入、输出、resize 和生命周期；官方示例包含 Electron main + IPC + xterm.js。采用，只在 Electron main 中运行（Windows 上用 ConPTY）。
xterm.js + FitAddon解释终端序列、生成原始输入并按 pane 计算 cols/rows。采用；不自定义终端协议。
Claude Code CLI在终端中运行的本地 CLI。使用本机安装的 claude，通过登录 shell 解析 PATH。
spawn + pipe适合非交互命令；缺少终端模式和 resize。不采用。

交互

Terminal

在当前项目目录打开登录 shell。切换标签页不会结束会话；关闭 Terminal 标签页会结束 PTY。

Claude Code

单独的入口在同一项目目录直接运行 claude。

失败状态

bridge、PTY 模块或 CLI 不可用时，标签页显示明确错误。Web 模式不显示交互控件。项目目录短时间内无法解析时，shell 在主目录启动，而不是留下空白页；启动后，迟到的项目响应不会让它重启。

主题与 ANSI

主题或自定义 CSS 改变时只更新 xterm 主题，不重启 PTY，也不丢失缓冲区。

终端工具栏

顶部显示预设、进程状态和实际 cwd；右侧提供复制、粘贴、清屏、重启和停止。按钮紧凑无边框；悬停和焦点遵循全站 token。

键盘与粘贴

Cmd/Ctrl+Shift+C 只在有选区时复制；Cmd/Ctrl+Shift+V 读取剪贴板并写入 PTY；普通 Ctrl+C 仍发送中断字符。Cmd+K 只清除当前 xterm 视口。

与 agent 共享

每个终端都是桌面宿主里的一个原生 PTY 资源，不论是谁打开的。agent 通过 terminal_use 工具使用它：list 列出终端，observe 某个终端以取得临时绑定和输出，然后 input、interrupt、resize、release 或 close，也可以在指定工作目录 open 一个私有终端。每个动作都使用 worker 签发（openprogram/host/resources/terminal.py）、由桌面宿主兑现的一次性票据。这个工具需要批准，在微信和 Telegram 会话以及计划模式下不可用，也不能绕过当前任务的沙箱。agent 的输入是原始按键，不是命令 API："delivered" 只表示输入到达了 shell，终端输出被视为不可信数据。人类输入不会暂停 agent，但输入版本变化时它要重新 observe 才能继续输入，并且从不自动重试不确定的输入。释放绑定会保留终端；关闭会结束 shell，必须是有意的操作。

数据流与信任边界

xterm.js ── write / resize ──▶ preload allowlist ──▶ Electron main ──▶ node-pty ──▶ login shell / Claude Code
◀──────── terminal:data / exit ────────◀
terminal_use ──▶ worker 票据 ──▶ 桌面宿主（terminal:agent-ticket）──▶ 同一个 PTY
  • renderer 只能选择 shell 或 claude 预设，不能提交任意可执行文件或 argv。
  • cwd 经 realpath 解析且必须是目录；PTY 绑定到 renderer sender 和终端 id。
  • 每次输入限制在 16 KiB；cols/rows 有上下界；替换进程会屏蔽旧进程的输出。
  • 进程跟随标签页生命周期；切换标签页只卸载 xterm 视图。关闭标签页、销毁 renderer 或显式停止会释放 PTY。
  • PTY 以本机 App 用户的权限运行，不提供远程沙箱。

范围

终端只在桌面 App 中提供。远程云会话、通用终端会话管理、shell 配置编辑器、持久命令历史和 Web 主机终端都不在范围内。终端标签页不影响其他标签页的会话、文件、浏览器、网页、书签、历史、分屏、关闭和拖动行为。

验收标准

  1. Terminal 标签页可以执行 pwd。
  2. Claude Code 入口直接显示本地 CLI；输入和 Ctrl+C 能到达进程。
  3. 项目列表正常响应时，cwd 是当前主项目；不响应时只短暂等待，然后在主目录提供交互 shell，不出现空白页。
  4. pane 宽度变化会同步 xterm 与 PTY 的 cols/rows。
  5. 切换标签页时 PTY pid 不变；单独关闭 Claude Code 不影响 Terminal。
  6. 深色/浅色、暖色和自定义主题变化会更新终端和 ANSI 16 色，PTY pid 不变。
  7. 复制、粘贴、清屏、重启和停止可用；Ctrl+C 保持中断语义；工具栏显示运行、已退出和错误。
  8. 专项检查、TypeScript 和 Web 生产构建通过。

Shell 目录与前台命令周期

现有桌面 PTY 资源为普通 macOS zsh 和兼容 bash 3.2 登录 shell 报告最近目录及前台命令周期。报告只供观察：零退出码不证明外部效果或 Agent 任务成功；前台周期结束后后台任务仍可继续。输入回执继续返回 phase=delivered 或未确认操作，command_complete=null。报告不改变归属、lease、审批、输入版本或取消状态。

元数据与传输

shell_integration?: {
  status: "starting" | "ready" | "unavailable" | "ended",
  mode: "zsh-hooks" | "bash-debug" | null,
  reason: string | null, event_sequence: number,
  cwd: { value: string, event_sequence: number } | null,
  cycle: { id: number, phase: "running" | "finished" | "unknown",
           exit_code: number | null } | null
}

既有资源读取与事件附加可选字段，旧宿主可不提供。start_cwd 不变，顶层 exit_code 属于 PTY 进程；嵌套 exit_code 仅属于匹配的 shell 周期。首次提示符报告 ready/cwd，cycle=null。进程退出使未完成周期变为 unknown，集成变为 ended；保留值仅为历史观察，不保证正在运行子进程的目录。Web 仅增加可选类型，不新增展示、提示符解析、命令 API 或 store。

启动兼容性

zsh 保留原生 -l。私有 .zshenv/.zprofile/.zshrc/.zlogin 转发文件在 source 各对应用户文件前恢复 ZDOTDIR 值和未设置状态，记录用户重定向，并在追加 preexec/precmd 回调前恢复最终目录。遵循 RCS，不强制启用被关闭的阶段。已有 hook 函数保留；只读回调数组拒绝安装。不声称任意全局启动脚本或插件配置等价。

bash 保留原生 -l；仅在启动环境未定义 PROMPT_COMMAND 时注入一次性初始化表达式。在 source 前于顶层捕获 DEBUG。未被覆盖且可写的初始化表达式安装最小 DEBUG/prompt 回调。已有自定义 DEBUG、只读 PROMPT_COMMAND、extdebug、functrace、被替换的 prompt command 和 bash-preexec 配置均不启用集成。终端保持可用并报告 unavailable，不覆盖用户 hooks。bash-preexec 回调注册不在当前实现中。父 PID 检查阻止嵌套 shell 提前取得初始化身份；回调拒绝非根进程和子 shell。不改用户配置、shell options 或历史策略。

协议与生命周期

帧格式为 ESC ] 777 ; OpenProgram ; 1 ; nonce ; rootPid ; eventSequence ; kind ; cycleId ; exitStatus ; cwdHex BEL。kind 为 ready、cwd、start、end。每次启动生成随机128-bit nonce；检查实际 PTY PID、严格递增的正安全整数事件序号、递增周期及匹配的完成。cwd 通过 printf/od/tr 编码为十六进制，限制16KiB UTF-8 绝对路径，拒绝 NUL 和无效 UTF-8。整帧最多36KiB。增量解析支持跨块，一秒后原样释放未完整候选。只有接受的有效帧在实时输出与回放存储之前统一移除；无关或无效内容保持原样，游标按同一输出流计算。

shell 内代码可读写自身 nonce，因此元数据不授予权限。不收集命令正文或环境转储。三秒未握手变为 unavailable，迟到的有效首次握手可恢复。不能从输出安静推断 hooks 丢失；最近报告可能过时。根进程退出使活动周期 unknown，不伪造 finished。

既有启动路径通过 Electron fs 读取单独登记的打包文件，写到每次启动0700目录及0600脚本，避免直接 source app.asar。spawn 失败或根进程确认退出时清理；视图重新连接、释放 lease 或隐藏面板不清理。旧代输出不能修改替换资源。不支持的 preset/platform 或资产准备失败保留原始终端。不新增设置、终端引擎、CLI 或 Windows 集成。

当前候选的 BEL 之前若出现后一个完整私有协议前缀，解析器将前面的畸形字节原样保留为普通输出，并从后一个前缀重新解析；前缀跨数据块时也遵循此规则。新候选仍须通过原有身份、序号、周期与长度检查。无效前置输出不能吞掉真实匹配的完成帧，也不能阻止后续周期完成。
