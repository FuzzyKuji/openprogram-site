Agent 控制提示层

agent 操作 macOS 原生窗口期间，OpenProgram 在该窗口上画三样东西：沿窗口边缘向内的强调色发光、变成强调色的关闭/最小化/缩放三颗灯，以及一直留在窗口里、滑向每一步的 agent 光标。agent 在网页标签页或对话的浮动预览里操作网页时，网页上也画同样的发光和光标，只是没有红绿灯。本文规定它们的外观与动效、使用的颜色，以及保证它们不妨碍用户的规则。

绘制位置

目标画什么代码位置
macOS 原生窗口（computer_use 窗口动作）向内发光、强调色红绿灯和 agent 光标，画在一个透明、点击穿透、不可聚焦的窗口里；每个对话一个，盖在受控窗口上，四周留 32pt 边距。window_watch.py 上报窗口位置；apps/desktop/main/worker/agent-control.js 摆放窗口；menu-overlay/agent-control 负责渲染。
桌面 App 中的网页：网页标签页或对话的浮动预览向内发光和 agent 光标，画在一个透明、点击穿透、不可聚焦的窗口里；每个网页一个，盖在它的原生视图上，四周留 24pt 边距，只在视图显示时显示。发光沿网页的圆角走：浮动预览是 10pt，标签页是圆角的底边两角。apps/desktop/main/windows/action-cues.js 摆放窗口，喂给它的数据和 agent-control.js 相同；渲染端上报 agent 持有哪些网页（bridge-events.ts 中的 subscribeAgentPageGlow）；menu-overlay/agent-control 负责渲染。
对话预览（PiP）和 Web 版agent 光标，画在预览图上方一个 pointer-events: none 的图层里。browser-control-bar.tsx 中的 ActionCueTravel。

所有界面使用同一个光标组件 AgentCursor。agent 持有网页期间网页发光：网页的控制状态是正在操作、仍在停止或尚未确认停止，并且它所在对话的运行还没结束。运行一结束，不论控制状态是什么，网页都算空闲，因为后端在最后一步之后、对账之前会一直把网页记为正在操作（browser-control.ts 中的 presentedControlState）；界面本身没有“暂停中”状态，也不在网页四周画框。网页标题栏和工具栏只在需要用户（需要你确认）或状态无法判断时出声。

窗口在哪里

会话持有一个窗口期间（从第一次读取或动作开始，到最后一步之后 20 秒，或 agent 换到别的窗口为止），worker 每 0.12 秒读一次窗口服务器的屏幕窗口列表，有变化时上报：窗口在屏幕上的位置（point），关闭、最小化、缩放按钮相对窗口的位置（通过辅助功能读取一次），以及挡在它前面、进入边距范围的窗口。App 自己的提示层窗口标题为 OpenProgram agent overlay，不计入遮挡。最后一次上报带 active: false，表示控制结束。上报以 native.control 帧传递，每一步的落点以 native.action 帧传递；两者只在显示操作打开时交给桌面端。

向内发光

  • 形状。 沿窗口圆角边缘（圆角 10pt）画一道 18pt 的强调色描边，模糊 11pt、不透明度 55%，并裁剪在窗口内，所以光从边缘开始、向窗口中间渐隐。边缘上没有描边线，窗口外不画任何东西。
  • 呼吸。 agent 持有窗口期间，发光以 2.6 秒为周期在这个强度的 60% 到 100% 之间呼吸。
  • 被遮挡的部分。 挡在受控窗口前面的窗口从发光和红绿灯中挖掉，提示层不会画到别的应用窗口上面。

标题栏红绿灯

  • 位置。 三个圆盖在关闭、最小化、缩放三个按钮上，按按钮区域等距排开，比按钮大半个点，让人一眼看出这个窗口正被 agent 占用。没有这三个按钮的窗口不画。
  • 外观。 每个圆填强调色，上面一层白色每 1.4 秒升到 40% 再落回，三颗依次相隔 0.2 秒。
  • 鼠标。 红绿灯和整个提示层一样忽略鼠标，点在上面仍然会点到下面的按钮。

Agent 光标

  • 图形。 App 图标库里的双色光标（Solar cursor，bold duotone），26px，强调色，尾巴为半透明；下面垫一层同形状的整块白色剪影（Solar cursor-bold）作白边，外露 2px，另加一层很淡的投影。
  • 热点。 光标方框以动作点为中心摆放，箭头尖端在动作点右下 2px，让点击圆点露在尖端旁边。元素的动作点是它在动作前的边界中心；坐标的动作点是截图坐标换算到屏幕上的点。
  • 停留。 在桌面应用上，只要 agent 还持有窗口，光标就停在上一步的位置，并随窗口移动。第一步从窗口中央出发。
  • 移动。 沿一条平缓的弧线滑到新的动作点（弯曲幅度为距离的 16%，最多 56pt），按距离在 240–680 毫秒内以 ease-in-out 曲线完成。网页光标移动方式相同。在 agent 持有的网页上，光标在两步之间停留；没有持有时显示的一步在 2.8 秒后淡出。
  • 按下。 到达点击、按下、选择、拖动或打开的位置后，箭头朝尖端缩到 82% 并在 0.26 秒内弹回，同时动作点上弹出一个带 2px 白圈的 8px 强调色圆点，停稳后在 1 秒内淡出。输入和滚动不按下、不留圆点。
  • 减弱动态效果。 系统要求减弱动态效果时，光标直接跳到位，关闭按下、圆点、呼吸和红绿灯脉动。

强调色

apps/web/app/styles/base.css 中 :root 的 --agent-accent 取主题强调色（--theme-accent），提示层跟随用户的主题配色。发光、红绿灯、光标和点击圆点使用它；白边、圆点的白圈和红绿灯的脉动是白色。提示层页面与 App 同源、共用主题设置，切换主题会立即生效。

安全规则

  • 不接收输入。 提示层窗口忽略鼠标，不能获得焦点，也不激活。所有界面都不移动系统指针。
  • 控制期间始终可见。 提示层在整个窗口会话期间保持显示，控制结束时在 0.36 秒内淡出。窗口最小化或在另一个桌面空间时隐藏，窗口回来后恢复。
  • 每个对话一个提示层。 两个对话控制两个窗口时，各自显示自己的发光、红绿灯和光标。
  • 只负责显示。 上报和绘制都不改变动作结果；失败时直接丢弃，步骤照常进行。

停止

提示层上没有停止按钮。提示层上的一切都忽略鼠标；可点击的区域会盖在受控应用上，拦截本该给应用的点击。停止仍在 OpenProgram 中进行：对话里的停止控件和 Running 面板。网页浮动控制条也没有暂停控件，只在 agent 等待确认时提供“查看请求”。

实现状态

macOS 和三处 Web 界面均已按本文实现。Linux 和 Windows 后端不上报窗口位置和动作点，那里不显示提示层。实时窗口捕获带来的 macOS 系统标记（标题栏按钮上的徽标和菜单栏的屏幕共享图标）仍会请求，但它不出现在截图里，所以由 App 自己的强调色红绿灯标出按钮。
