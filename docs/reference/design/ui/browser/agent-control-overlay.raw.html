Agent control overlay

When an agent operates a native macOS window, OpenProgram draws three things over that window while the agent holds it: an accent glow along the inside of its edge, its close, minimize and zoom lights turned to the accent, and the agent cursor, which stays in the window and glides to each step. When the agent operates a webpage in a page tab or the chat's floating preview, the page gets the same glow and cursor, without the lights. This page sets their look and motion, the colour they use, and the rules that keep them out of the user's way.

Every surface draws the same cursor component, AgentCursor. A webpage glows while the Agent holds it: the page's control state says the Agent operates it, is still stopping, or is not yet confirmed stopped, and its conversation's run is still going. Once the run has ended the page is idle whatever its control state says, since the backend keeps a page active after its last step until it reconciles (presentedControlState in browser-control.ts); the interface has no pausing state of its own and draws no frame around the page. The page header and toolbar speak only when the reader is needed (Needs your confirmation) or the state cannot be told.

Where the window is

While a session holds a window (from its first read or step until 20 s after the last step, or until the agent moves to another window), the worker reads the window server's on-screen list every 0.12 s and reports, when anything changed: the window's frame in screen points, the frame of its close, minimize and zoom buttons relative to the window (read once through Accessibility), and the windows in front of it that come within the margin. The App's own overlay windows carry the title OpenProgram agent overlay and are left out. A last report with active: false ends control. The reports travel as native.control frames, the step points as native.action frames; both reach the desktop shell only while Show actions is on.

Inner glow

  • Shape. An 18pt accent stroke along the window's rounded edge (10pt corners), blurred by 11pt at 55% opacity and clipped to the window, so the glow starts at the edge and fades toward the middle. There is no line on the edge itself and nothing is drawn outside the window.
  • Breathing. The glow breathes between 60% and 100% of that strength every 2.6 s while the agent holds the window.
  • Covered parts. Windows in front of the controlled one are cut out of the glow and the lights, so the overlay never draws on top of another app's window.

Title-bar lights

  • Position. Three circles over the close, minimize and zoom buttons, spaced across the buttons' frame and half a point larger than them, so the buttons read as taken while the agent works. A window without those buttons gets no lights.
  • Look. Each circle is filled with the accent, and a white layer on it rises to 40% and falls back every 1.4 s, the three in turn 0.2 s apart.
  • Mouse. The lights ignore the mouse like the rest of the overlay; a click there still reaches the button under it.

Agent cursor

  • Glyph. The app's icon set's two-tone cursor (Solar cursor, bold duotone) at 26px in the accent, its tail at half strength, laid on a white keyline cut from the same shape in one piece (Solar cursor-bold), which shows 2px around it, plus a faint contact shadow.
  • Hot spot. The cursor's box is centred on the action point, and the arrow's tip rests 2px right of and below it, so the click dot shows beside the tip. For an element the point is the centre of its frame before the action; for coordinates it is the screenshot point mapped to the screen.
  • Stays. Over a desktop app the cursor stays where the last step left it for as long as the agent holds the window, and moves with the window. The first step starts it from the middle of the window.
  • Travel. It glides to each new point along a gentle arc (the curve bends by 16% of the distance, at most 56pt) with an ease-in-out curve over 240–680 ms, depending on distance. The webpage cursor travels the same way. Over a page the Agent holds it stays between steps; a step shown without a hold fades after 2.8 s.
  • Press. On arriving at a click, press, selection, drag or opening step, the arrow dips to 82% toward its tip and springs back in 0.26 s, and an 8px accent dot with a 2px white ring pops in at the point, settles and fades out within 1 s. Typing and scrolling neither press nor leave a dot.
  • Reduced motion. When the system asks for reduced motion, the cursor jumps instead of gliding, and the press, the dot, the breathing and the pulsing lights are off.

Accent colour

--agent-accent on :root in apps/web/app/styles/base.css is the theme accent (--theme-accent), so the overlay takes the colour of the user's theme. The glow, the lights, the cursor and the click dot use it; the keyline, the dot's ring and the lights' pulse are white. The overlay page shares the App's origin and its theme settings, so a theme change reaches it at once.

Safety rules

  • No input. The overlay window ignores the mouse and cannot take focus or activate. None of the surfaces moves the system pointer.
  • Visible while in control. The overlay stays up for the whole window session and fades out in 0.36 s when control ends. A minimized window or one on another Space hides it until the window is back.
  • One overlay per conversation. Two conversations controlling two windows each show their own glow, lights and cursor.
  • Display only. Reporting and drawing never change an action's result; a failure is dropped and the step goes on.

Stopping

The overlay has no Stop control. Everything on it ignores the mouse; a clickable area would sit over the controlled app and catch clicks meant for it. Stopping stays in OpenProgram: the conversation's stop control and the Running panel. The webpage floating control has no Pause control either; it offers only Review request while the Agent waits for confirmation.

Implementation status

Implemented as described on macOS and on the three web surfaces. Linux and Windows backends report neither window places nor step points, so no overlay shows there. The macOS system marker that a live window capture adds (a badge over the title-bar buttons and the screen-sharing icon in the menu bar) is still requested, but it does not show in screenshots, so the App's own accent lights are what mark the buttons.
