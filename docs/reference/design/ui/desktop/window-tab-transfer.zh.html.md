# 在窗口之间移动标签页

桌面端的标签页可以离开所在窗口，落到另一个 OpenProgram 窗口里，或者落到松手位置新建的窗口里。移动是一次事务：结束时标签页只存在于一个窗口，任何一步失败都让源窗口保持原样。网页标签页保留它的活页面。

相关：[`center-tabs-and-split-layout.html`](../workspace/center-tabs-and-split-layout.html)（单窗口内的标签栏、分组与分屏），[`window-lifecycle.md`](window-lifecycle.md)（主窗口与拖出的窗口）。代码：`apps/desktop/main/web-views/transfers.js`（主进程协调器）、桌面端的 `tab-transfer-validation.js` 与 `tab-transfer-store.js` 模块、`apps/web/lib/tabs/transfer/`（渲染进程的拖拽协调器与日志）、`apps/web/lib/tabs/store/transfers.ts`（标签 store 的插入与移除）。

## 移动的内容

一次转移携带三种来源形态之一：

| 来源类型 | 内容 |
|---|---|
| `tab` | 恰好一个未分组的标签页 |
| `segment` | 复合分组中的一个成员；分组其余成员留下 |
| `group` | 整个复合分组，连同成员、可见成员和焦点成员 |

所有中心标签类型都能移动：会话、文件、网页、新标签页、应用和内置页面。负载还携带目标窗口按原样显示标签页所需的信息：来源位置（分组 id、成员序号、成员顺序、可见成员、焦点成员、画布布局）、未保存的文件草稿，以及每个对话的状态（输入框草稿、输入框设置、待定项目、渠道选择、该对话是否处于活动状态）。每个标签页的页面历史随之一起移动。

主进程在接受负载之前校验它。字符串和嵌套值都有上限；整个负载最多 20 MiB，文件草稿每次最多 3 份、每份 2 MiB、合计 6 MiB。格式不对的负载拿不到令牌。

## 网页保留状态

网页标签页是归属于某个窗口上下文的 Electron `WebContentsView` 对象。移动网页标签页移动的是**同一个视图对象**：协调器把它从源窗口的 content view 移除，再加到目标窗口。它从不调用 `loadURL`，所以重定向、登录状态、表单值、滚动位置、页面内存和 DevTools 协议目标都在移动后保留。目标渲染进程报告新的边界之前，视图保持隐藏。

重新挂载之前，协调器清除页面上的 agent 操作提示和控制叠层，记录每个视图的边界与可见性，并确认源窗口仍拥有每个视图。处于进行中转移的视图会被锁定，第二个转移或 agent 命令不能同时占用它。

## 事务

每次转移由一个不透明的一次性令牌标识，15 秒内未完成即过期。

```
源渲染进程                主进程                         目标渲染进程
─────────────────        ────────────────────────      ────────────────────
prepare(payload)  ─────▶ 校验，签发令牌
                         （状态：prepared）
                                                ◀────── inspect(token)
                                                        （只允许一个窗口）
                                                ◀────── accept(placement)
                         锁定视图，重新挂载
                         （destination-staged）  ──────▶ 插入标签，写日志
                                                ◀────── destination-ready
                         （awaiting-source）
移除标签，写日志 ◀────── remove-source
source-removed    ─────▶ 持久化 "committed"
                         决议，显示窗口
                         （committed）
```

- **准备。** 拖拽离开标签栏时，源渲染进程同步申请令牌。
- **检视与接受。** 指针下方的窗口检视令牌；源窗口和第二个窗口都不能检视。接受时锁定并重新挂载视图。目标也可以以 `duplicate`（它已经有这个标签页，并聚焦自己的那份）或 `group-full` 拒绝；源窗口收到通知，什么都不改变。目标完全无法校验的负载不会被接受，其令牌到期失效。
- **目标先行。** 目标先插入标签页并报告就绪，然后源窗口才移除自己的那份，所以任何时刻都有一个活的标签页。
- **提交。** 主进程在报告成功之前，用原子替换把 `committed` 决议写入应用数据目录下的 `tab-transfers.json`。如果这次写入的持久性不确定，协调器以 100 ms 起、最长 5 s 的退避重写同一决议；如果决议根本写不进去，转移回滚。
- **新窗口。** 在所有 OpenProgram 窗口之外松手时，在松手位置创建一个隐藏的拖出窗口。它认领待处理的令牌，像普通目标一样接受，等标签页就位后才淡入显示，所以不会先闪出一个空窗口。并发的拖出请求共用一次窗口启动。
- **源窗口变空。** 如果源窗口没有剩余标签页，它在日志完成后关闭。

指针下方的目标窗口会收到悬停进入与离开事件，只在拖拽经过它时显示落点。

## 日志与恢复

每个渲染进程在修改自己的标签 store 之前，先在以窗口为键的本地存储（`openprogram.tabTransferJournal:<windowId>`）里写一条日志。日志保存修改前后的标签布局、会话状态、文件草稿和原生视图簿记，所以渲染进程在重载或崩溃后可以应用任意一侧。主进程记录哪些角色打开了日志；持久化的决议把它们列为必需角色。

重载后，渲染进程查询待处理的终态决议，把 `committed` 或 `rolled-back` 应用到自己的日志，然后完成自己的角色。所有必需角色都完成后，决议被删除。如果拥有某个角色的窗口已经不在，另一个活着的窗口接管这个孤立角色并完成它。

## 回滚

以下情况转移回滚：过期；目标或源失败；显式取消（Escape，或拖拽结束时没有目标）；参与的窗口被销毁或尝试关闭；提交决议写不进去。

- 还没有任何日志打开时，回滚只丢弃令牌并通知源窗口。
- 之后的回滚：协调器写入 `rolled-back` 决议，请目标撤销插入（限时 2 秒），再把每个视图按原边界和可见性还给源窗口。为这次转移创建的拖出窗口被关闭，其状态丢弃。
- 如果源窗口已经不存在，转移中的视图会被关闭，而不是留成无主视图。
- 已提交的转移永不回滚。

普通的关闭规则不适用于转移：移除源窗口那份不会产生关闭记录、不会删除草稿，也不会在目标确认收到之前打开兜底的新标签页。

## 移动后的路由

菜单命令和 agent 的网页标签命令只发给获得焦点的窗口。原生视图消息只接受来自拥有该视图的窗口的渲染进程，所以移动后的页面立即听从新窗口。
