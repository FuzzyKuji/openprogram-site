Composer 选项菜单

范围：ControlsCluster 中的选项（+）菜单。本文是它的设计与验收清单。

选项菜单就是全应用通用的那套 radix 下拉——components/ui/dropdown-menu.tsx 的 DropdownMenu / DropdownMenuContent / DropdownMenuItem——铺在 components/chat/top-bar/menu-styles.ts 的共享菜单 token 上：玻璃材质的 MENU_PANEL 画框（10px 圆角、6px 衬）、itemCls 行（24px 高、13px 字、6px 圆角、hover 是唯一底色）、通铺的 MENU_SEPARATOR，以及右对齐的勾列（CHECK_SLOT / CHECK_SLOT_PAD）。它没有自己的 module CSS。

行

从上到下：添加文件或照片、录制 Workflow（仅 macOS 桌面 App）、分隔线、网页搜索、沙箱、分隔线、无人值守。每一行都是 PlusMenuRow（controls/menu-pieces.tsx）：一个穿着 itemCls(false) 加 MENU_ITEM_STATES 的 DropdownMenuItem，后者把 radix 的键盘高亮和禁用属性映射到同一条 hover 规则上。布局就是共享文法——16px Solar 图标列、标签、可选的右侧元数据、再是勾列。选中行显示 14px 墨色 check-circle，在变为选中的那一刻弹入一次；其余行用 CHECK_SLOT_PAD 占住这一列，所以标签和勾与顶栏菜单落在同一竖列。开关类行（网页搜索、沙箱、无人值守）通过阻止 radix 的 select 保持菜单打开；添加文件让菜单关闭。沙箱不可用时是禁用行，保留原生 title 说明原因。

没有工具开关

菜单里没有 Tools 开关，也没有 Access preset。对话能调用哪些工具由 Agent 配置决定（Agents → 能力 → Programs：全部、指定范围或 Access preset、不使用）。不该调用工具的对话，用一个 Programs 设为"不使用"的 Agent。输入框只在 Agent 工具集之上叠加网页搜索（见 tool-toggle-management）。

参考实现比较

方案能力结论
共享菜单 token 上的 radix 下拉受控打开状态、portal、带翻转与碰撞处理的浮动定位、roving focus、typeahead、Escape、外部点击；与顶栏、Recents、标签页菜单同一套包装与 token采用；全应用一种菜单文法
Base UI Menu 加 CSS module 样式行为相同，但多一个菜单库，以及一份手工维护、已与共享样式分叉的画框和行样式已移除；选项菜单是唯一使用者
手写 fixed 定位与遮罩能做点击状态，但缺 portal 层序、自动翻转和完整的键盘 / 焦点行为不采用；重复已有基础设施
原生 Popover API有顶层和轻量关闭，但缺菜单的 roving focus 与定位约定不采用；会维护两套菜单语义

DOM 与层级

菜单通过 radix portal 渲染到 body，层级 z-[200]，高于 composer 自己的层；radix 把内容的 z-index 复制到 popper 包装上，并负责锚定、翻转和碰撞。打开参数为 side="top" align="start" sideOffset={9}。不涉及信任、隐私、并发或取消边界：这只是本地呈现。

验收

生产文件：apps/web/components/chat/composer/controls/controls-cluster.tsx、controls/menu-pieces.tsx、components/chat/top-bar/menu-styles.ts。回归入口：npm run check:composer-options-menu。

  • 选项画框、行、分隔线和勾都来自 menu-styles.ts；composer.module.css 没有 .plusMenu* 规则。
  • 菜单没有 Tools 行、没有 Access preset 二级菜单，旁边也没有 Tools 标签。
  • 不存在 menuPosition 或手写 fixed 坐标。
