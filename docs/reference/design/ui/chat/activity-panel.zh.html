Activity 面板#

右侧栏的 Activity 列出一个会话的主代理（它启动的子代理在它的页面里），单独列出它们在 shell 里运行的程序和命令，再列出会话自己持续在做的事：常驻唤醒、未完成事项和在这个会话里设置的定时任务。在等读者的事不单独成组，而是它所关联的那一行，图标右上角带红色数字，和程序坞里 App 的角标一样。状态用常见的词：正在运行、已完成、失败、已取消、已中断、等你回答、等你授权；没事的行只显示时间。消息从不成行，留在聊天里。

相关：indicator-dots.md（状态圆点）， sub-agent-row.md（子代理自己的对话）。 代码：apps/web/components/right-sidebar/running/running-panel.tsx、 apps/web/lib/execution/activity-model.ts、 openprogram/runtime/execution/activity_calls.py、apps/web/lib/chat/conversation-work.ts、 openprogram/interfaces/server/routes/execution/conversation_work.py。

分支、运行与等待#

子代理是显示类型为 job_agent 的执行。每个执行都属于一条分支：子代理负责它自己，以及它下面没有被更深一层子代理接管的执行；其余都属于主代理。子代理挂在它上方最近的那个子代理下面，没有的话就挂在主代理下面。

底层的执行组成运行：一个顶层执行，通常是一条消息加上为它做的所有事。子执行、尚未返回的函数调用和托管程序归属于包含它们的运行。运行有自己的页面（从主代理的“最后一条消息”、子代理的“来自”或停在问题上的消息进入），但不单独成行。

已返回的 agent 调用会和它启动的子代理配对。服务端从对话记录里读取这些调用：Job 记录了派生它的回复（spawn_caller）和它的提示词，调用方相同、提示词相同的那次调用就是启动它的调用；没有失败的调用先配对，因为失败的调用可能和重试用了同样的提示词。提示词对不上时，如果一个调用方只剩一个 Job 和一次没有失败的调用，就把它们配成一对。没有配到 Job 的调用就是没有启动成功（结果是 [agent error] … 或 outcome 为 failed）或没有启动。记录行的 caller 说明是哪条分支发起的调用：j_… 开头的回复属于子代理，其余属于主代理。这里不读 effects：它们的元数据里带着完整的模型请求，读起来太慢。

只有停在问题或授权上的运行才算在等读者（模型的 issues 里筛出暂停的执行）。被重启打断的调用或运行显示为“已中断”，监督进程不在的程序显示为“状态未知”：两者都是历史记录，用弱化色，没有要做的事。

只缺模型响应记录（provider_response_incomplete）的执行显示为已结束。

总览#

五组，顺序固定；空的组不显示，组标题都不带数量。组标题用侧栏的 SectionHeader：鼠标移到组上显示折叠三角，点标题把这一组收起到标题。哪些组收起是视图偏好，和 Agents 的视图一起保存在这个浏览器里（lib/prefs/activity-view.ts）。

  1. Agents：只有主代理一行（会话自己的 agent，命名和图标与子代理一致）。主代理显示为正在运行（写出当前调用或“等待子代理”，以及已用时间，蓝色）、“失败 · 时间”（红色），否则只写最后一条消息的时间，后面跟模型启动的子代理个数（“10月15日 · 5 个子代理”）。在等你的事（它自己的运行和子代理的）是幽灵图标上的红色数字。子代理本身列在主代理页面里，所以不管模型启动多少个，概览都只有一行。执行不在列表里的调用和程序算作主代理的。

    会话有不止一个分支时（读者在 DAG 里分叉、编辑消息产生的分支），每个分支都是一个独立的主代理，各占一行、地位相同：分支名、用分支泳道色画的幽灵图标、当前检出的分支带“当前”标签，状态和子代理汇总都只按这个分支上的运行计算（服务端的 branches[].execution_ids；子代理归属它顶层运行所在的分支）。执行不在列表里的调用和程序、没有建出子代理的调用，算作当前分支的。分支页面就是这个分支的主代理页面，标题写“分支”，不是当前分支时带“切换到这个分支”按钮（和分支面板里的切换一样）。没有列出运行的分支显示分支自己的时间。子代理自己的对话不算这里的分支：旧会话把子代理的对话存在同一个会话里，它的末端沿前驱链能追到一个派生根节点，服务端的分支行（build_branches_payload）把它标成 sub_agent，这里不列出。

  2. 程序和命令：正在运行的 shell 调用、运行被中断时还没返回的 shell 调用（“命令 · 已中断 · 昨天”，弱化色），以及所有后台程序。正在运行的排前面，然后是其余的，每类内部从新到旧，每次 20 个。命令的状态写出类型（“命令 · 正在运行 · 12 秒”）。程序以它做的事为标题（bash 调用的 description；没有时用它运行的脚本或模块名，跳过 cd、mkdir 这类准备步骤），标题下用等宽字体显示命令。运行中状态行就是进度（“45 / 100 samples · 3.4/s”），下面一条细进度条，右端写剩余时间（“剩 16s”）；不知道总量时显示已运行多久和最后一行输出，进度条来回流动。结束后写出结果（“已完成 · 10 / 10 epochs · 4 分 5 秒”“失败于 62 / 200 · exit 1”）。程序结束后，它的记录和输出保留一天（openprogram/host/processes/store.py 的 RETENTION_SECONDS）；supervisor 失联（“状态未知”）的程序，从最后一次心跳起保留一天。之后 worker 的进程巡检会删除它，还没发出的退出通知也一并丢弃：晚了一天的通知已经过时。agent 调用不出现在这里，通过对应的 agent 进入。

  3. 常驻：会话的 Agent 设为常驻时有一行“常驻 · ”。唤醒的那一轮进行中显示“正在工作”（蓝色），否则显示目标状态和“下次唤醒 <时间>”。还没加入的会话显示“下次使用后加入”。

  4. 未完成事项：会话的未完成事项（未完成事项），每项一行，“未完成 · <时间>”。完成的事项不再出现在总览里。

  5. 定时任务：在这个会话里设置的定时任务、提醒和 webhook（任务的 session_id，或签名执行规格里的），从新到旧，写出类型和运行时间（“Webhook · 被调用时”“周期 · 0 9 * * 1-5 · 检查结果变化时”）。

调用和程序在执行列表读取之后才归位，不会先闪现为无归属。第 3 到 5 组来自同一次读取 GET /api/sessions/{id}/work：打开面板时、收到 always_on_update、always_on_report 和 open_work_update 帧时、窗口获得焦点时读取，并每 30 秒读一次，因为定时任务没有自己的事件。

页面#

每一行点进去都是一个页面；面板背后是一个页面栈，返回箭头写出要回到的页面。任何地方都不原地展开。

  • 主代理：会话标题（一行）和状态。先列在等你的事（每条写出是哪条消息），然后是“正在运行”、“最后一条消息”（点开那次运行的页面）和“子代理”：所有子代理，深度优先、从新到旧。第一层就是这个页面自己的列表；更深的子代理缩进挂在启动它的那个子代理下面：一条细折线从那个 agent 的图标下方连到它自己的图标，线继续延伸到它后面的兄弟行；上方还有后续兄弟行的 agent，它们的线也会穿过这一行。子代理显示为正在运行及当前调用、已中断（被打断的 agent 调用以它启动的子代理身份显示），或最终状态加时间；在等读者的只在原位出现一次，显示时间，幽灵图标上带红色数字（只数它自己的；下面的子代理各带各的）。没有建出子代理的 agent 调用放在树里那个子代理本该在的位置，显示为“没有启动成功”或“没有启动”。列表每次显示 20 行，点“显示更早”继续。

    这一节标题右边的按钮打开视图菜单，用输入框选项菜单的同一套部件搭成：同样的 radix 封装和 MENU_PANEL 外框，每项设置一行、点开是子菜单，子菜单里是带勾的选项行。“显示”可选全部、等你处理（带红色数字的行）或正在运行（运行色的行）。按结构时，筛选保留每个匹配项及其上方的 agent（pruneBranches），按剩下的行重画连线。“排列”可选按结构（树）或按时间：一个平铺列表，正在运行的在前，其余按行上显示的时间排，每个子代理的状态末尾写出是谁启动的（“· Research启动”）。筛选后什么都不剩时，在标题下写明，菜单仍然可以打开。视图不是默认值时按钮保持高亮；视图是按浏览器保存在 local storage 里的偏好。

  • 子代理 / 运行：类型、开始时间和用时、名称或消息、状态。它在等的问题或授权排在最前，操作是浮起的胶囊按钮。暂停在一个已排队的决策上（pendingDecisions，按执行匹配）时，显示它的问题和可选项，“去聊天里回答”/“去聊天里授权”滚到输入框上方的决策卡片（data-decision-output）并聚焦第一个控件；选择在那里完成，不在 Activity 里。没有排队决策的暂停在运行页自己的记录里（见下）回答；从主代理页，“打开”进入那个页面。单个这样的暂停在列表和页面上显示为“等你回答”或“等你授权”。子代理另有“打开它的对话”、“由谁启动”（主代理或上方的子代理）、“来自”（启动它的那条消息对应的运行），以及取自 agent 调用的“任务”。然后是“步骤”：未返回的调用（agent 调用通过它启动的子代理进入）、子执行、它启动的子代理和没有启动成功的调用、程序。最后是“进展”下这次运行自己的记录：DebuggerPanel 的 embedded 布局（没有自己的标题和滚动区），先列进展行，然后是原因和执行允许的控制（暂停、继续、单步、重试、补充指令、创建分支）、未回答的等待，以及折叠在“技术详情”里的原始 id、修订、检查点和事件。打开运行页就在检查器 hook 里选中这次执行，它只在运行页打开时读取事件和调试数据。不再有单独的检查器页面：一次运行就是一页，主代理页也没有自己的检查器。

  • 没有启动成功：调用的说明、发起时间和“没有启动成功”，一句说明它没有自己的对话，然后是“由谁启动”、报错那一行和任务。

  • 调用：以说明为标题，显示类型、开始时间、状态、来自哪次运行，以及任务（prompt）或命令。被打断的调用显示“已中断”，并有一句说明运行在它返回前中断了。任务按正文显示，命令用等宽字体；都先显示几行，点“展开全文”看全部。

  • 程序：标题和列表行一致。最上面是进度卡片：数量和百分比、进度条，运行中再显示已用时间、速度和剩余时间，结束后显示用时、结束时间和退出码。然后是运行中的“停止程序”、命令，以及按终端方式显示的输出：用回车重绘的行只保留最后一帧，颜色保留，读者停在末尾时自动跟随新内容（标为“实时”）。最后是来自哪次运行、有描述作标题时的程序名、工作目录和运行环境。打开的程序页面每秒读取一次。

  • 常驻：Agent 名称、会话标题和状态，说明会话如何唤醒、如何停止（归档会话；计划属于 Agent）的一段话，立即唤醒，然后是常驻目标、当前目标、唤醒间隔、上次唤醒及结果、下次唤醒，以及报告：每条报告的标题、时间、正文、链接和发送去向。

  • 未完成事项：这一项、添加时间和状态，标为完成（完成后变为重新打开）和删除，然后是备注。

  • 定时任务：标题和计划，webhook 的地址和密钥（复制），它监视的命令，它的提示词、提醒或命令，以及在定时任务中打开，在那里暂停、修改或删除任务。

程序进度#

服务端从程序输出里读出进度（openprogram/host/processes/progress.py），按可信程度依次是：程序主动打印的 ##progress 45/100 samples 行（bash 工具会提示模型在长循环里打印）、OSC 9;4 终端进度序列、tqdm 和 pip 进度条，以及 Epoch 3/10、step 120 of 1000、[45/100] 这类计数。更可信的来源出现过之后，不再采用较不可信的来源，所以内层每个 batch 的进度条不会覆盖明确的样本数。速度和剩余时间取进度条自带的值，或从计数开始时测量。输出按终端显示的样子保存，重绘的进度条只占 2000 行上限中的一行，agent 读取后台命令时每次重绘只拿到一次。

外观#

行在静止时没有框：裸露的类型图标用该类型的颜色，名称下面是一行状态，按状态着色，不带圆点，右侧一个箭头。悬停时整行浮起成卡片：用文件卡片的阴影，底色向文字色偏一档（4%）的实色，因为面板本身就是输入框那层底色，同色卡片看不出边缘。行叠在树线上方，浮起的卡片和它的阴影盖住连线，而不是被线穿过。连线是一种实色：把弱化文字色混进面板自身的背景色，而不是半透明描边，所以各段在拐角处重叠也不会变深。页面上在等你的事用浅琥珀色底，没有边框。
