观察到的行为

11–14 秒原生刷新到对话记录出现。
0.18–0.20 秒直接的首次历史请求。
16 次恢复在第一个历史请求之前处理；一次刷新加载五次历史。

测得的基线重连路径会在所选对话之前发送每一个持久化的执行游标。服务端按连接串行处理命令。重放快照进入实时执行更新路径，而该路径会为已结束的执行再请求一次对话记录。游标存储保留已完成的执行，并在每个游标帧上同步持久化。部分持久化的执行流包含超过 200 MB 的事件负载。当前 Web 端的重放处理器只消费由此得到的执行快照。因此恢复读取请求仅快照模式：执行记录和事件游标在同一个 SQLite 事务里读出，不读取事件正文。显式读取事件历史的客户端保持原有行为。

状态归属与数据流

对话记录每个会话与视图代次只有一个请求负责方。持久化消息、分页、搜索目标和滚动锚点。
执行单调递增的游标与状态版本、活动任务与审批身份。快照恢复不会模拟出新的终止事件。
输入框归会话所有的草稿、附件、排队条目和确认。导航或断线从不清除尚未确认的输入。

连接代次拥有计时器、待处理的读取请求和分片缓冲。过时的响应不能修改新的连接或可见会话。存储失败只降低持久化能力，不影响事件投递。服务端对授权、执行、取消和审批保持权威。任何客户端优化都不绕过这些边界。

对话记录读取生命周期

每个连接对每个会话只有一个待处理的首次或刷新请求。导航复用已有的读取；修改操作使其失效，并保留一个带最新选项的替代请求。每个响应回显其请求 ID。过期、被替代和连接已关闭的回复会被忽略。读取有 15 秒期限，并以会话为单位显示加载中、已断线或失败状态，附带重试按钮。缓存的消息保持可见。请求开始后发生变化的实时消息优先于该请求的快照。现有的消息存储仍是权威；不引入第二个对话记录存储。

分页保留现有的窗口与代次检查。快照游标无效时，围绕当前阅读锚点发起一次不带游标的读取；失败保持可见并可重试。如果续期失败，针对该无效快照的自动翻页停止。显式重试使用保留所请求分支头的无游标锚点读取；锚点不存在时另有读取最新历史的操作。路由缓存渲染复用现有的消息存储，保留线上缓存中没有的实时行。加载状态切换不会重置指数退避的重试延迟。读取重试从不重复修改、提交、审批或取消命令。

流式输出与阅读

文本和思考增量按回复合并为每个动画帧一次的存储更新。历史请求在记录基线之前，先冲刷该会话已收到的增量。接受响应时，在合并前冲刷之后到达的增量，因此只有请求之后收到的进度才能覆盖其快照。历史清理只释放该会话的消息路由；另一个窗格待处理的流仍按计划进行。连接关闭和卸载时，在清除旧连接的路由和缓冲之前冲刷已收到的进度。工具与终止事件保持立即冲刷的顺序。现有的有界历史窗口、按测量回收的行、按需加载的完整工具输出和独立的跟随锁仍是渲染的基础。

实施顺序

  1. 集中处理重连与执行恢复，区分恢复出的快照与实时状态转换，使游标持久化具备韧性。普通 UI 恢复使用原子的仅快照读取；显式检查保留完整的事件重放。
  2. 集中历史请求归属、导航代次、过期游标恢复，以及加载/错误/重试的呈现。
  3. 验证并优化长历史渲染、流式批处理、工具输出展开、滚动跟随和跳转行为。
  4. 补全草稿、排队/确认/重试/取消/引导、审批、后台任务和无障碍的交互覆盖。
  5. 运行合并验证，更新一次默认 App，并测量完整的场景矩阵。

每个阶段都经过独立的规格与质量评审。一个阶段通过不代表整个前端完成。本设计不包含新的执行运行时、远程服务、账户集成或历史数据删除。

对话加载期间的资源投影

资源轮询与对话记录水合共用 worker。每次资源列表请求在所有可见资源之间复用同一个对话图、同一个前驱索引，以及记忆化的来源与分支名结果。当前分支查询可以使用另一个独立的图快照。这些值只在该请求内存活；下一次请求会看到分支重命名和分支头变化。资源可见性、执行归属、控制对账和稳定的分支引用选择仍是权威。原生验收暴露了按资源重复读取 DAG，以及历史响应超过 15 秒读取期限的问题。该修复通过了独立的规格与质量评审、一项公开资源端点回归测试和完整的合并验证清单。在受影响的对话上，同等的资源查询耗时从 5,741–5,760 ms 降到 124–147 ms；这些是资源查询的测量值，不是整页加载时间。

实现证据

集成后的实现通过了独立评审和完整的自动化验证，其中包括原生验收中发现的资源投影修复。恢复顺序、仅快照读取、关联的历史请求、可见的重试、按会话划分的流式缓冲以及现有的交互基础都通过了独立的规格与质量评审。最终的集成候选版本还保留了失败回复的详情、流式引导中断和已停止轮次的历史。

合并清单通过 10,480 个 Python 测试、964 个 Web 测试和 168 个浏览器测试，报告 138 个 Python 跳过、一个预期的 Python 失败和 20 个浏览器跳过。结构检查、类型检查、生产构建、文档链接和 diff 检查均通过。聚焦的回归测试验证：恢复从不读取历史事件负载正文，快照记录与游标一致，旧的读取回复不能替换之后的进度，已取消的缓冲不能让回复复活，已取消的引导草稿在历史对账后不会自动发送。

浏览器矩阵覆盖有界的大历史渲染、锚点恢复、游标续期失败与键盘重试、对等会话隔离、草稿与附件归属、排队回执、停止与引导顺序、提问重新挂载、输入法、窄布局和减少动态效果。本地发布台账记录确切的实现与集成提交、评审结论和闸门日志。已安装 App 的验收仍是单独的发布要求：发布报告负责已安装的版本、目标对话的重载测量、更早历史的导航、草稿保留和原生视觉证据。上面的数字是基线测量，不代表优化后的 App。
