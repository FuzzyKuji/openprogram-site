Programs 代码结构

Agent 能调用的一切都是 Program。内置工具位于 programs/tools/，始终可用；内置应用位于 programs/applications/，可以启用或停用；用户自己的 Program 位于 ~/.openprogram/programs/。每个加载的包都通过自己的 ProgramContext 注册，卸载时会移除它添加的一切。模型调用经过两个原语 llm() 和 agent()，以及用于具名角色的 Agent 类。

状态：当前设计范围：源码、注册、Programs UI、打包

1. 目录结构

openprogram/
├── runtime/agent/
│   ├── llm.py                  # llm()：一次模型调用
│   ├── agent_function.py       # agent()：模型工具调用循环
│   └── agent_class.py          # Agent：带方法的具名角色
└── programs/
    ├── __init__.py             # 解析 API：TOOLSETS、DEFAULT_TOOLS、agent_tools、apply_tool_policy
    ├── tools/                  # 内置工具，始终提供给 Agent
    │   ├── files/  code/  web/  interaction/  knowledge/  jobs/
    │   ├── agents/  computer_use/  runtime/  system/
    │   └── planning/           # todo/  plan_mode/  open_work/  goal/
    ├── applications/           # 内置应用，整体启用或停用
    │   ├── browser/            # 标签页、Page 与 web_use
    │   ├── workflow_recording/ # 演示录制器
    │   └── office_editor/      # ONLYOFFICE 文档编辑器
    ├── _authoring/             # Program 代码导入的内容：errors、json_parsing、reports/、helpers ...
    └── _host/                  # 宿主如何加载和运行 Program；Program 代码不导入它
        ├── runtime.py          # @function 与共享工具注册表
        ├── context.py          # ProgramContext，每个所有者一个
        ├── registry.py         # 内置、用户与 harness Program 的加载器
        └── packages.py  sources.py  execution.py  services.py  ui/ ...

~/.openprogram/programs//   # 用户的 Program：Python 包、应用、harness 克隆
每项能力只有一个权威实现和一个公开 import 路径。programs/ 下没有 functions/、workflows/ 或 packages/ 目录，旧路径也没有兼容别名。

2. Program 的三个来源

programs/tools/

内置工具

Agent 离不开的能力：文件、shell、搜索、规划、询问用户、记忆、任务、网页和计算机操作。它们随核心发布，始终提供给 Agent，不能逐个停用。多数在导入时用 @function 注册；带 PROGRAM_ENTRIES 的工具包通过自己的 ProgramContext 注册（所有者 tool:<name>）。

programs/applications/

内置应用

browser、workflow_recording 和 office_editor。每个都通过所有者为 application:<name> 的 ProgramContext 加载，提供核心访问它所用的具名服务，只在启用时加载（openprogram programs enable|disable <name> 或 Applications 页面）。

~/.openprogram/programs/

用户 Program

列出 PROGRAM_ENTRIES 的 Python 包（如周报或研究循环这类 Workflow）、带 application.json 的应用目录，以及 openprogram programs install 记录的 harness 克隆。它们与内置 Program 走同样的 context；包规范见 Workflow。

可迁移包来源

项目内 Program 使用带 programs 范围的相对路径记录位置；一个外部安装绑定负责连接已安装 runtime 与源码 checkout。相对路径不使用聊天的工作目录。只有已授权的确切包名参与 Python 解析，不扩展整个外部目录的 import 范围。拒绝条件与发布规范以 Workflow 包合同为准。

3. 基础原语与 Workflow

Workflow定义流程、状态与验收
→
agent()带工具的多轮模型推理
→
llm()单次模型请求与结构化输出
入口含义位置
llm()一次不带工具循环的模型调用。runtime/agent/llm.py
agent()模型工具调用循环。runtime/agent/agent_function.py
Agent具名角色，其方法执行模型调用，方法可以作为工具提供。runtime/agent/agent_class.py
goal()启动一个跨普通聊天轮次保持目标的聊天 Goal；属于会话状态，不是原语。programs/tools/planning/goal/

Workflow 是调用这些原语和其他 Program 的普通 Python。凡是进行模型调用、调用其他 Workflow，或保存多阶段状态与完成检查的能力都是 Workflow；包装在角色里的单次模型调用也是。

4. Goal 以普通聊天轮次运行

单一机制
Goal 是 programs/tools/planning/goal/ 中的会话状态。每个成功的聊天轮次结束后，chat.py 决定是否为活动 Goal 再启动一个普通聊天轮次。没有独立的 Goal 循环、裁判 Workflow 或嵌套工作 Agent。
Programs 表单
goal(prompt) 只接收目标。它在当前对话中保存聊天 Goal，路由通过与 /goal 相同的控制启动第一轮。
聊天命令与 Agent 工具
/goal <目标> 与 Agent 的 create_goal 工具创建同一种聊天 Goal。goal Program 从不作为工具提供给 Agent。
完成
update_goal(status="complete") 或完成的 todo 计划只提交候选。verification.py 运行一次独立只读验证轮次后，Goal 才算达成。
限制与重启
Goal 没有轮数限制。连续两个自动轮次没有工具调用时，Goal 以停滞状态停止。可选的 token、活动时间和费用限制是仅有的预算。租约属于上一个 worker 的 Goal 重启后以暂停状态恢复，并提供继续操作（restart.py）。

5. 选择文件还是目录

形式适用场景示例
单个 .py一个公开入口和少量本地辅助函数，文件可以独立阅读。tools/files/edit.py
同名包多个职责不同的模块、资源文件或会话适配器。tools/planning/goal/、applications/browser/
内部目录只服务相邻代码的共享实现；名称以 _ 开头，不成为 Programs UI 节点。programs/_authoring/、programs/_host/

是否拆包由文件数量和职责边界决定，而不是为了统一形式。

6. 允许的依赖方向

调用方允许禁止
Tool标准库、批准的依赖和确定性辅助函数。llm()、agent()、Workflow、Application。
WorkflowTool、自己的角色、无循环依赖的其他 Workflow。依赖 Application、复制其他 Workflow、按字符串名称调度。

Program 代码programs/_authoring/ 和公开 runtime API。programs/_host/。

7. 注册与 Programs UI

共享注册
_host/registry.py 加载内置工具、已启用的内置应用、用户的 Program 和已记录的 harness。每个包通过自己的 ProgramContext 注册，按所有者保存（tool:<name>、application:<name>、用户包名、external:<package>）；卸载或重新加载时释放它。
Programs 树
树只镜像源码目录。已注册条目可运行，显示 Use。展开同名包会按实际目录列出其模块（如 goal/command.py）；这些文件可以打开阅读，但不注册为额外 Program。__init__.py 和 _ 目录从不成为节点。
稳定契约
移动源码不改变公开名称、参数 schema、权限、DAG 语义或会话状态格式。旧路径直接失败，没有别名，也不双路径扫描。

8. 不采用的设计

没有 workflow 装饰器

没有 @workflow；分类由目录和元数据表达。

没有字符串调度

Workflow 使用普通 Python import 和调用，没有 call_workflow(name)。

没有并行结构

不按版本并存新旧目录，也不在运行时选择其一。

9. 工具参数的动态 mapping

工具的 canonical schema 区分调用时才确定键名的 mapping 与声明固定字段的对象。公开 program.args 接受已注册程序合法的关键字参数，包括 task。匿名 object mapping 与 Python dict/Mapping 注解保留开放键名及已声明的值类型。含 properties 的对象，包括显式空字段集合，保留固定字段限制。显式 additionalProperties: false 不会被打开；nullable mapping 保留原有 null 语义。

Canonical 对象本地验证Provider 工具模式
匿名或 typed mapping接受合法动态键，验证 object 与已声明的值类型保留 mapping schema，使用非 strict 工具模式
声明固定字段或显式关闭对象保留必填字段、类型与额外字段拒绝支持时使用 strict 模式
两类工具同时出现在请求中每次调用按各自 canonical schema 验证逐工具选择模式，从不对整个请求关闭 strict 验证

共享 provider schema adapter 从不把开放 mapping 转成只能为空的关闭对象：models/providers/schema/strict.py 拒绝把含动态键的 schema 变成 strict。OpenAI function calling 要求 strict 模式使用关闭对象，因此动态 mapping 工具在 Responses、Codex 与 Chat Completions 中显式发送 strict: false，可兼容的固定字段工具继续 strict。Anthropic 同样逐工具启用 strict 验证；mapping 工具保留普通 input schema，不设置 strict 标志。固定的 execute_code schema 保持 strict。
