# 路由总览

Settings → Providers 的总览面板回答一个问题：哪个会话、它的哪条分支在和哪个模型说话，模型失败时发生了什么。它只是把运行时已经保存的记录拼起来看；为它专门新增的记录只有改道一项。

## 数据来源

`GET /api/routing/overview?window=<秒>`（`openprogram/interfaces/server/routes/settings/routing.py`）合并：

| 来源 | 提供什么 |
|---|---|
| 会话索引（`list_sessions`） | 标题、`source` / `channel`、当前轮次的 `running` 状态 |
| 会话节点图（`list_branches`、`SessionNodeWriter.load`） | 每个打开的分支末端、分支上最后一条回复的模型、末端是否从子 Agent 的派生根开始 |
| 用量账本 `usage_events` | 时间范围内每个会话、每个模型的调用；`parent_session_id` 指向另一个会话的行就是那个会话的子会话 |
| 用量账本 `route_events` | 每次改道一行：发起调用的会话、失败的 `provider/model`、下一个 `provider/model`、原因 |
| 凭据库 | 用到的 provider 的每个账号：状态，以及限流冷却何时结束 |

会话满足以下任一条件就会列出：当前轮次正在运行、在时间范围内更新过、账本在范围内有它的调用。最多列 8 个，正在运行的排前面，其余按最近活动排序；剩下的计为空闲。每个会话最多显示 4 条分支，当前分支排第一。

## 通道（lane）

会话下的每一行是一条通道，各自连到一个模型：

- `branch` —— 一个打开的分支末端。链最长的末端是主干，标为 `main`；其余用分支名。
- `sub_agent` —— 链从子 Agent 派生根开始的末端。
- `children` —— 按调用的模型归组的子会话，带数量。
- `calls` —— 没有回复节点、但账本里有调用的会话（程序直接调用模型）。
- `background` —— 账本里不属于任何已列出会话的调用：带自己 `op-…` id 的程序运行时、起标题、记忆整理等。它们按模型归在同一个「后台调用」条目下，这样图上的数量和上面的调用总数对得上。

通道是当前末端且会话轮次在运行，或者最近 90 秒内账本有它的调用时，算作正在进行。打开会话要从磁盘逐个文件读出整张节点图。每次读文件都会让出 GIL，服务器其他线程忙的时候每次都要排队等回来，冷打开一个会话可能要好几秒。两条规则让请求保持快速：会话和它的通道按 `(会话, 索引里的 updated_at)` 缓存，没变化的会话不会再被打开；冷会话在一个后台线程里打开，请求最多等 1.5 秒。到时还没打开好的会话先用索引行和账本里的调用显示，响应带上 `partial: true`，客户端两秒后再取一次。

## 改道

`stream_with_failover` 每次从失败的候选模型换到下一个时，追加一行 `route_events`，并用用量上下文里的会话做标记。会话最近一次改道落在当前通道的模型上时，总览从这条通道画一条虚线到失败的模型，在失败的模型上标出原因，并在图下列出最近的改道。只有配置了备选模型才会有改道；没有改道、直接把错误显示给用户的失败不在这里记录。

## 客户端

`apps/web/components/settings/providers/routing-overview.tsx` 画两列 HTML，背后一层 SVG。连线端点在布局完成后和尺寸变化时从渲染出的行上量出，所以名字多长都行。切换时间范围会取消上一个范围的请求，新数据到达前当前内容变淡。正在进行的连线上有移动的小点；鼠标停在某条通道或某个模型上时保留它的连线，其余变淡。面板宽度不足 560 px 时放不下两栏和中间的连线，面板会隐藏连接图，提示用户折叠侧边栏或把窗口拉宽。
