# 配置 Agent

在侧栏打开 **Agents**。Agent 保存可重复使用的模型、指令、能力范围、记忆权限和频道对话设置，不要求绑定某一种专用任务。

页面打开时每个 Agent 是一张卡片，显示它的[头像](#头像)、模型、思考强度、程序以及是否常驻。卡片支持按名称、ID 和描述搜索。点击 **新建 Agent**，输入名称并选择模型；内部 ID 自动生成。

点一张卡片，会在卡片旁打开它的快速设置：名称、描述、模型、思考强度和常驻，以及 **试运行草稿** 和 **新对话**。**打开完整设置**（或能力旁的 **管理**）把卡片收成左侧的列表并打开完整编辑区；编辑区顶部用一排标签显示同样的概览，点标签会打开对应分区。列表顶部的 **全部 Agent** 返回卡片。

| 分区 | 配置内容 |
| --- | --- |
| 常规 | 显示名称、描述、[头像](#头像)、Provider、模型和思考强度 |
| Programs | 自动提供工具、指定程序或关闭程序 |
| Skills | 可用技能和排除项 |
| MCP | 允许、排除和必需的服务器 |
| 长期记忆 | 关闭、只读或读写，以及读取和写入范围 |
| 上下文 | 频道对话隔离、空闲重置和每日重置 |
| 常驻 | 按计划唤醒，推进常驻目标并报告发现（[常驻 Agent](always-on-agents.zh.md)） |
| 高级 | 频道身份、提及规则、可选指令，以及哪些 [AGENTS.md](agents-md.zh.md) 文件生效 |

所有分区共用一份草稿，**保存**写入完整配置。切换 Agent 或执行会丢弃草稿的操作时，可以选择保存、放弃或取消。保存失败会保留草稿。其他编辑器先保存时，先比较当前草稿与最新版本，再选择保留哪一份。保留草稿不会立即覆盖最新版本，需要复核后再次保存。

模型选择器读取 Provider 目录，不修改其他对话的模型。选择“上次使用的模型”时，对话使用你最近一次使用的模型。不可用模型或不兼容的思考强度会保留显示，直到明确修改。缺少必需的 MCP 服务器时，在请求模型前停止执行。

## 头像

每个 Agent 都有头像。凡是出现这个 Agent 的地方，头像都在它的名字旁边：本页的卡片和编辑区、输入框里的 Agent 按钮和它打开的菜单、非默认 Agent 回复上方的名字、[运行记录面板](../interfaces/web.zh.md#会话运行记录)的常驻行，以及设置里的频道绑定。

没有设置头像的 Agent 显示一个由它的 ID 决定的角色：一个带两只眼睛的彩色形状。同一个 ID 总是得到同一个角色，内置 Agent 各有一个符合其工作的角色。要换一个，在完整编辑区打开 **常规**，使用 **头像**：

| 类型 | 选择内容 |
| --- | --- |
| 角色 | 22 种形状之一和 8 种颜色之一 |
| 生成 | 生成的图案：先选风格，再选变体 |
| 上传 | 不超过 256 KB 的图片文件（PNG、JPG、SVG、WebP 或 GIF；动图会播放） |

头像属于 Agent 的草稿，和其他设置一样点 **保存** 才写入；复制 Agent 时头像一并保留。

凡是代表某个 Agent 的地方，角色都是活的：会眨眼、晃动、自己东张西望，在运行记录面板里 Agent 工作时还会显出忙碌的样子。头像选择器里的形状格是静止的图案。系统开启“减少动态效果”时，所有角色都静止。

## 内置 Agent

每个实例自带一组内置 Agent，相当于 Grok Bot 自带的 bot 模板：每个都是针对一类工作的完整配置，以普通 Agent 卡片的形式保存。服务启动时安装这个实例从未装过的那些，之后它们就是你的：点卡片开始对话、修改、复制或删除。删掉的不会被重建。

其中三个是 Agent 类的固定参数配置，没有自己的提示词；任务由调用处及 Context 提供：

| Agent | 用途 | 能力 |
| --- | --- | --- |
| 决策 | 通过 `Agent.choose()` 从给定选项中选择一项 | 一次模型调用，不使用工具或自动重选 |
| 轻量助手 | 提取、分类、格式转换、摘要，以及按需预测候选下一句 | 不启用工具 |
| 统筹规划 | 规划依赖、委派已授权任务、检查结果 | 读取、检索和 Agent 协作工具 |

在常规分区中，为轻量助手选择低价模型，为统筹规划选择较强的推理模型。名称不保证费用或输出质量。预测的下一句话只是候选，不代表授权；只要求规划不授权执行委派。这三个初始关闭记忆、Skills 和 MCP。

其余的每个只做一件事。每个都有一段 system prompt，写明职责、交付物、绝不做的事、完成标准、工作方式和第一个任务；这件事需要的工具且仅此而已；在自己空间上的记忆策略；以及常驻默认值。它们的常驻初始全部关闭，等 Agent 有了可以工作的对话，再到常驻标签页打开。

| Agent | 职责 | 工具 | 记忆 | 定时巡检 |
| --- | --- | --- | --- | --- |
| 统筹助理 | 推进待办、把任务交给其他 Agent、汇报 | 读取、网页、对话、未完成事项、交接、提醒、目标 | 读写 | 每 2 小时 |
| 需求规格 | 把需求写成带验收标准的规格 | 读取、网页、对话、写文件 | 只读 | 否 |
| 缺陷复现 | 找到最小失败用例并钉成失败的测试 | 读取、shell、代码导航、worktree | 关 | 否 |
| 实现 | 在 worktree 里实现已写明的改动并带测试 | 读取、shell、编辑、worktree | 关 | 否 |
| 评审 | 对照规格和测试检查改动；从不改代码 | 读取、shell、代码导航 | 关 | 否 |
| 研究简报 | 跟踪主题、阅读来源、维护带引用的简报 | 网页、PDF、写文件、提醒 | 读写 | 每 4 小时 |
| 收件箱分拣 | 分拣新消息并起草回复；不会发送 | 读取、对话、写文件、提醒 | 读写 | 每 30 分钟 |
| 求职侦察 | 扫描招聘网站、排序匹配、准备申请 | 网页、浏览器、PDF、写文件 | 读写 | 每天两次 |
| 知识库管理 | 把结束的对话提炼进记忆，合并、修正 | 读取、对话、编辑文件 | 读写 | 每天 |
| 文稿 | 把材料写成要求形式的成稿 | 读取、网页、编辑文件、画布、图片 | 只读 | 否 |

实现和评审故意是两个 Agent：写改动的 Agent 永远不给自己放行。处理邮件或帖子的 Agent 止于草稿；任何权限模式下，对外发送都等你批准。它们通过[会话之间的交接](always-on-agents.zh.md#把工作交给另一个会话)协作：给每个 Agent 开一个对话、起清楚的标题，并告诉统筹助理（或负责规划的那个对话）哪个对话做什么。

Python 可以直接调用已保存的 Agent：

```python
from openprogram import Agent
from openprogram.runtime.agent_registry import manager

helper = Agent.from_spec(manager.get("utility"))
result = helper("从这句话提取城市：活动在新加坡举行。")
```

单选调用提供选项 ID 和内容，返回选中的 ID：

```python
selector = Agent.from_spec(manager.get("decision"))
selected = selector.choose("判断这句话的类别。", {"A": "提问", "B": "陈述"})
```

`choose()` 使用当前 Context 和 DAG，关闭工具与网页搜索。非法答案抛出 `DecisionError`，不再次请求模型重选。模型和思考参数由调用者配置；该入口不增加推理或顾问工作流程。普通 `__call__()` 仍可用于常规模型回答。

`openprogram.runtime.agent_registry.builtin_agents` 的 `create_builtin_agents()` 就是安装操作：创建这个实例从未装过的内置 Agent，已有记录连同修改原样保留。服务在启动时、已有默认 Agent 的前提下运行它；setup 创建 Main 时也运行它。读取注册表从不安装 Agent。

## 开始对话和试运行草稿

**新对话**使用已保存的 Agent 配置。**试运行草稿**将当前草稿用于独立对话，不保存 Agent。首次发送消息时记录该试运行的配置快照，后续消息和恢复执行继续使用这份快照。试运行不写长期记忆：已保存配置或草稿关闭记忆时保持关闭，其余情况最多只读。

### 更换对话的 Agent

输入框底部一栏、模型旁边的 Agent 按钮显示这个对话使用的 Agent。点开可以换成其他已保存的 Agent；[常驻](always-on-agents.zh.md)的 Agent 标有 **常驻**。在尚未发送的对话里，选择从第一条消息起生效。在已经开始的对话里立即切换（正在运行一轮时不能切换）：之后的轮次使用新 Agent 的指令、能力和记忆；新 Agent 设置了模型时，对话改用它的模型。之前的消息保持不变。菜单底部的 **管理 Agents** 打开本页，Agent 的设置在这里修改。

多个尚未发送的对话分别保留 Agent 选择和覆盖设置。发送某个对话不会使用其他标签页的 Agent。首次发送被拒绝时保留选择，支持重试。在未发送的 Agent 对话中改选模型，只影响该对话。

保存后的指令、能力设置和记忆设置用于该 Agent 的后续执行。已有对话保留创建时（或上次更换 Agent 时）的模型和明确设置的思考强度；未设置思考强度时使用当前 Agent 默认值。对话中的显式覆盖仍然生效。试运行对话保留自己的快照。上下文分区中的重置规则适用于频道对话，新对话和试运行均使用新历史。

## 记忆权限

新 Agent 默认关闭记忆。旧配置没有记忆字段时，保留对旧版共享记忆的访问。**此 Agent**将记忆单独保存；**旧版共享记忆**引用已有的 profile 共享存储。读写模式的写入位置必须同时位于读取范围中。

关闭模式禁止框架记忆读写。只读模式允许读取，但不提取或新增记录。后台提取和派生结果保留已记录的写入限制，重新开启记忆不会补录此前受限的 turn。关闭记忆或删除 Agent 配置不会删除已存储的记忆。这些设置约束框架记忆操作，文件系统工具访问仍由相应权限控制。

启用**要求记忆可用**后，记忆不可用会阻止执行；否则执行继续，但不使用记忆，并记录降级状态。[Memory 页面](memory.zh.md)介绍已有共享存储的编辑方式，不用于浏览各 Agent 的独立记忆空间。

## 未完成事项

每个对话有一份未完成事项清单，记着眼前的事做完后 Agent 在这个对话里仍欠你的事，比如在等的回复、答应过的检查、你还没回复的草稿。这些事项在这个对话的每一轮都写在 Agent 的指令里，[运行记录面板](../interfaces/web.zh.md#会话运行记录)也会列出。Agent 用 `open_work` 工具添加和完成事项；也可以在聊天里让它添加、修改或删掉某一项，或在运行记录面板里标为完成。完成的事项留在清单历史里（最近 50 条），不再出现在指令中。其他对话也要知道的事应写进[记忆](memory.zh.md)。

未完成事项不是[任务清单](../interfaces/web.zh.md#任务清单)：任务清单规划眼前这件事的步骤，事情做完就结束。

## 复制和删除

复制会保留配置并生成新 ID，不复制对话或独立记忆。`self` 引用解析为新 Agent 的独立空间；明确配置的旧版共享引用仍指向共享存储。删除默认 Agent 前，需要先将其他 Agent 设为默认。
