# 常驻 Agent

常驻 Agent 让它的会话在你离开时继续工作。使用它的每个会话都会按计划唤醒，推进常驻目标；没有事做时用只读工具巡检新情况；发现值得你关注的事就通知你。

常驻是 [Agent](agents.zh.md) 配置的一部分，和模型、指令、能力、记忆一样。它做的事发生在会话里：和这个 Agent 的每个会话都是一个独立的常驻助手，各有自己的目标、巡检和报告。想要两个互不相干的常驻助手，就开两个会话。

## 开启

1. 在侧栏打开 **Agents**，选择要设置的 Agent。
2. 打开 **常驻** 标签页，勾选 **让使用此 Agent 的会话常驻**。
3. 可选：填写 **常驻目标**，例如“保持文档站没有死链，有需要我审阅的修复时告诉我”。
4. 选择唤醒频率（**唤醒间隔**，5 到 10080 分钟，默认 60）。
5. 可选：在 **何时唤醒** 下选择唤醒的日子并设置 **安静时段**（见下文）。
6. 点 **保存修改**。
7. 和它对话：在 Agents 页面点 **新对话**，或在任意对话输入框的 Agent 按钮里选它。

## 安静时段与唤醒的日子

默认情况下，会话全天按间隔唤醒。在常驻标签页的 **何时唤醒** 下：

- **唤醒的日子**：计划唤醒发生在哪几天（周几），至少保留一天。
- **安静时段**：每天一段不做计划唤醒的时间，填写 **开始** 和 **结束**，例如 22:00 到 08:00。结束早于开始表示跨过午夜。

两者都按本机的本地时间。落在安静时间里的唤醒会顺延到它结束时，例如 08:00 或下一个唤醒日，运行记录面板显示的下次唤醒就是这个时间。安静时间里，**立即唤醒** 和来自你其他会话的消息（见下文）照常处理，已经在运行的目标也会继续。

## 哪些会话会唤醒

开启常驻后，你用过的会话会加入：新开的对话，或你在里面发过消息的旧对话。用 Agent 按钮把对话换成这个 Agent 也算。加入后过一个间隔才第一次唤醒，所以刚打开的对话不会被打断。开启后没用过的会话保持安静。

子代理会话和导入的会话不会唤醒。归档会话即可停止它的唤醒；在 Agent 上关闭常驻会停止所有会话。重新开启后，之前加入过的会话从那一刻起重新计算间隔。

## 每次唤醒做什么

每次唤醒最多做一件事：

| 情况 | 结果 |
| --- | --- |
| 计划唤醒落在安静时段或不唤醒的日子 | 什么都不做；下次唤醒顺延到安静时间结束 |
| 会话里已有一轮正在运行 | 什么都不做，下次再试 |
| 设置了常驻目标，且这个会话还没开始 | 在会话里把它作为[目标](goal.zh.md)启动 |
| 有目标正在进行或已暂停 | 什么都不做；目标会自己继续，你手动的暂停保持不变 |
| 没有要推进的目标，且开启了巡检 | 进行巡检（见下文） |
| 其他情况 | 什么都不做 |

如果修改常驻目标时还有未结束的目标，新目标会在它结束后开始。想马上切换，在会话里输入 `/goal clear`。

常驻目标要写成一件要达成的事（“让文档站没有死链”），不要写成例行事务（“每小时检查一次链接”）。条件满足后目标就结束；之后再查是巡检做的事。

## 巡检

没有要推进的目标时，会话会巡检。Agent 回顾记忆、这个会话的[未完成事项](agents.zh.md#未完成事项)和会话本身里的未完事项，并查找新情况。巡检只能用只读工具：读文件和搜索、网页搜索与抓取、读会话和记忆，以及读取任务清单、未完成事项和目标。巡检时不能运行命令、修改文件或调用 MCP 服务器。

发现值得你关注的事，它会发一条报告；否则用一句话说明没有发现。在 **巡检可以做什么** 中选择：

- **只报告发现**（默认）：在报告中提出建议，由你决定是否开始。
- **可自行开始目标**：可把发现转为目标，之后按会话正常的工具和权限执行；也可以把它交给负责这类工作的另一个会话（见下文）。

关闭 **没有目标时进行巡检**，它就只为常驻目标唤醒。

唤醒就是会话里普通的一轮，所以它做过的事都在会话里，你也可以像平常聊天一样回复它。它的权限模式和规则就是这个会话的设置；需要授权时会在会话里等待并通知你。

## 把工作交给另一个会话

会话可以组成团队，每项工作只有一个负责者：负责规划的会话可以把任务交给专门做这类工作的会话，例如把“检查链接”交给文档会话。在 Agent 为常驻的会话里，Agent 有一个 `handoff` 工具，可以给你的另一个会话发消息，用标题或 ID 指定对方。对方会话可以使用任何 Agent。

- 消息作为对方会话的下一轮到达，显示为以 📨 和发送方标题开头的消息。如果对方正有一轮在运行，会等它结束，最多十分钟。
- 那一轮结束后，它的回答作为新的一轮回到发送方会话，显示为以 ↩️ 开头的消息。如果对方一直忙，消息会原样退回。
- 每一轮都按所在会话自己的 Agent、权限模式和规则运行。在“询问”模式下，发送交接和其他操作一样要等你授权；在“自动”模式下会经过审查。
- 会话不能给自己发消息，一串消息和回复最多四跳。子代理会话、导入的会话和已归档的会话不能发送也不能接收交接。
- OpenProgram 服务重启后，一天内的交接链仍然有效：跳数照常计算；重启时正在处理消息的会话，处理完后仍会把回答发回去。

要组建团队，给每个会话起清楚的标题、分好工作，并告诉负责规划的会话哪个会话做什么。

## 会话的运行记录面板

Agent 设为常驻时，会话的[运行记录面板](../interfaces/web.zh.md#会话运行记录)有一行 **常驻**，显示会话正在做什么、下次何时唤醒（已顺延过安静时段）。打开后可以看到常驻目标、当前目标、唤醒时间安排、上次唤醒及结果，以及这个会话的报告。**立即唤醒** 会马上唤醒一次。

## 报告与通知

报告包含标题、简短正文和可选链接。它在会话里显示为一次工具调用，也会出现在运行记录面板里；会话不在屏幕上时，侧栏会给它标上未读圆点。没有发现可报告内容的巡查不会留下未读圆点，运行记录面板仍会显示它的结果。在桌面 App 中，没有 App 窗口处于焦点时，每条报告都会弹出系统通知，点击即打开对应会话。

## 把报告发到渠道

报告也可以发到你的[聊天渠道](../integrations/channels.zh.md)（Telegram、Slack、Discord 或微信）。在常驻标签页的 **同时把报告发到** 下勾选要收到报告的会话，最多 10 个。它们适用于这个 Agent 所有会话的报告。

列表包含此 Agent 已有的渠道会话，以及通过联系人绑定（`openprogram channels bindings add <agent> --channel telegram --account <id> --peer <id>`）绑定的人和群组。绑定到整个渠道或账号的 Agent，只会列出和它聊过的人。

每条报告先保存在 App 中，再向每个选中的会话各发送一次。运行记录面板会在每条报告下显示是否已发到各个会话。发送失败（例如账号已退出登录）也会显示在那里，报告本身仍然保留。

## 从反馈中改进

Agent 通过记忆改进。在 Agent 的 **长期记忆** 标签页选择 **读写**：你在会话里给的纠正和偏好会存入它的记忆，并在之后的对话中使用。记忆不是读写时，常驻标签页会提示你。

## 限制

- 工作在本机运行，使用会话的工作目录和沙箱。worker 必须在运行，会话才会唤醒。
- 安静时段和唤醒的日子按本机的时钟和时区计算。
- 复制出的 Agent 默认关闭常驻。

[工程设计](../reference/design/runtime/always-on-agents.zh.md)介绍了唤醒、巡检、报告和交接的实现方式。
