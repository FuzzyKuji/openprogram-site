# 有事发生时运行任务

[提醒](reminders.zh.md)和定时任务按时间运行。另外两种触发方式在有事发生时运行任务：一条命令的输出变了，或者别的服务调用了 webhook。直接用自然语言提：

- "每 10 分钟检查一次 `gh pr list --repo me/app`，有新的 PR 就告诉我。"
- "给我一个 webhook，用来分拣我们工单系统里的新工单。"

Agent 用 `scheduler` 工具设置它们。每个触发都运行你给的任务：一段 Agent 提示词、一个在本对话里唤醒 Agent 的提醒，或一条 shell 命令。

## 有变化时

周期任务和监控任务可以带一条 `watch` 命令。这时 cron 表示多久检查一次这条命令，只有命令输出和上一次检查不同时，任务才运行。第一次检查只记录基线，不运行任何东西；换了命令会重新记基线。

运行时会收到变化内容，即输出的 diff。命令和其他定时命令一样在任务的沙盒里运行，必须在 2 分钟内结束。检查失败或超时不运行任务，基线保持上一次的。

## 被服务调用时

`webhook` 任务没有时间表。创建后会给出一个 URL 和一个 key：

```text
POST http://127.0.0.1:18100/hooks/<任务 id>
X-OpenProgram-Key: <key>
```

这个 key 也可以填作 GitHub webhook 的 secret：GitHub 用它给每次投递签名（`X-Hub-Signature-256`），运行时会知道 GitHub 的事件名。key 不对或任务不存在都返回 `404`；任务已暂停返回 `409`。同一个任务每 10 秒最多启动一次，期间的调用返回 `429`。请求体最大 64 KB，运行收到其中前 8000 个字符。

这个 URL 在本机上。互联网上的服务只能通过你自己搭的隧道或[公开的 Web 地址](../server/configuration.zh.md#谁能连上这个服务)访问到它。

## 外部文字只是数据

启动运行的文字（请求体或变化的输出）来自外部。运行收到的是用 event 包起来、标为数据的内容：Agent 被告知只做你交给它的任务，忽略事件里的任何要求。

这样启动的运行也不会不经询问就动手：

- 提示词任务在后台运行，没人可问，所以需要审批的调用一律被拒绝。
- 唤醒 Agent 的提醒，在对话处于 Bypass、Auto 或 Accept edits 时改用 **Ask** 模式开始回合，每个改动都要你在该对话里批准。
- shell 命令从环境变量 `OPENPROGRAM_EVENT` 拿到事件，`OPENPROGRAM_EVENT_SOURCE` 为 `webhook` 或 `watch`。

## 查看、暂停或删除

监控变化的任务和 webhook 任务和其他任务一起列在 **Scheduler** 里；webhook 任务的时间一栏显示 **被调用时**。可以在那里暂停、恢复或删除，也可以让 Agent 去做。每次运行的日志（包括启动它的事件）在 scheduler 的 `logs` 文件夹里。
